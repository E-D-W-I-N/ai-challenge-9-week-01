# AI Challenge — стенд сценариев

Одно локальное веб-приложение на все задания первой недели челленджа:
прогоняет сценарии дня и показывает их результаты рядом, колонка к колонке.
Сейчас в нём пять дней, девять сценариев и 21 колонка.

Выбираете сценарий в списке слева, жмёте «Старт» — колонки идут параллельно,
каждая на ходу показывает свои метрики, а внизу стенд подводит сводку по прогону.

Слева стенд раскладывает сценарии по дням: заголовок дня, под ним его сценарии.
День отдаёт столько сценариев, сколько в нём пунктов задания, — каждый в 1–3
колонки, чтобы они помещались на экран без горизонтального скролла.

К моделям стенд ходит через [OpenRouter](https://openrouter.ai): API совместим
с OpenAI, каждая колонка спрашивает свою модель, а `usage.cost` приходит в ответе.

## Запуск

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000 — слева список сценариев по дням.

`.env` в `.gitignore`. Репозиторий публичный: ключ, попавший в коммит, отозвать уже
нельзя. Никогда не коммитьте через `git add -A`.

Дропдаун моделей работает и без ключа: каталог `/api/v1/models` авторизации не требует.


## Что показывает стенд

Колонка устроена как чат: сверху лента сообщений, под ней метрики, внизу поле
ввода. Промпт из `Session.messages` стенд показывает **до** старта: `system` идёт
приглушённым блоком и сворачивается по клику, `user` — заметным пузырём. Ответ
модели стримится под ними как `assistant`. У колонки с `depends_on` до старта
подсвечен литерал `{{depends_on}}`, а на старте стенд перерисовывает ленту
итоговым промптом — уже с подстановкой.

Колонку можно прогнать не один раз, а серией: `Session.repeats` говорит, сколько
раз подряд отправить тот же запрос. Каждый прогон встаёт в ленте отдельным
блоком со своей строкой метрик, а над панелью метрик колонки стенд считает долю
уникальных ответов — «уникальных ответов: N из M». На этом построен День 4:
разброс от `temperature` виден только на серии. Судье уходят все ответы серии,
а не только последний.

Колонки занимают всю высоту экрана, и высоту у них не отбирают ни блок
«Вердикт», ни сводка. Оба встают **под** экраном колонок — к ним прокручиваются,
а ленты стенд не сжимает. Горизонтального скролла нет ни при какой ширине;
внутри колонки скроллится только лента. Колонки делят ширину поровну, на узком
экране встают друг под друга. Список сценариев сворачивает кнопка в его шапке —
освободившаяся ширина уходит колонкам, и свёрнутым он останется после
перезагрузки. В шапке сценария стенд держит одну строку: название, селекторы
моделей и «Старт». `description` он на экран не показывает — тот уходит
модели-судье.

В поле под лентой можно **писать модели руками** — до прогона и после
(`POST /api/chat`). В модель уходит вся накопленная лента колонки, поэтому
диалог продолжается; параметры стенд берёт из `Session`, модель — из селектора
в шапке. Enter отправляет, Shift+Enter переносит строку. Без ключа поле
недоступно и говорит, чего не хватает.

Когда все колонки отработали, под ними появляется блок **«Вердикт»**. Отдельная
модель-судья отвечает на вопросы задания дня: сравнивает ответы колонок
и формулирует вывод. Её ответ стримится так же, как ответы колонок.
Судью стенд зовёт один раз за прогон и только у сценариев, где заданы
`judge_questions`, а стоимость этого вызова показывает в сводке отдельной строкой.
Подробности — в [docs/CONTRACT.md](docs/CONTRACT.md).

Под колонкой стенд на ходу считает время до первого токена (TTFT), скорость
в ток/с, сгенерированные токены и прошедшее время, а из ответа берёт токены
`prompt`/`completion`/`total`, reasoning-токены, стоимость в долларах,
`finish_reason`, модель, фактического провайдера и заполнение контекста.
В сводке он складывает стоимость и токены всего прогона, показывает wall-clock
и стоимость судьи, а когда колонок больше одной — называет самую быструю
и самую дешёвую.

## Добавить день

Создайте `day-NN/scenario.py` по [docs/CONTRACT.md](docs/CONTRACT.md): объявите
`SCENARIOS` — список сценариев дня, `id` каждого начинается с имени папки
(`day-02-format`) и уникален глобально. Реестр подхватит их при следующем запросе
списка — трогать `app/` не нужно. День, нарушивший контракт, попадёт в ошибки под
списком сценариев и не сломает остальные дни.
