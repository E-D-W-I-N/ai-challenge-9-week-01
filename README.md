# AI Challenge — стенд сценариев

Одно локальное веб-приложение для записи демо-видео по дням челленджа.
Открываете стенд, выбираете сценарий, включаете запись экрана, читаете описание
и «на что смотреть», жмёте «Старт» — колонки split-screen стартуют параллельно,
у каждой живая статистика, внизу сводка по прогону.

Слева сценарии сгруппированы по дням: заголовок дня, под ним его сценарии.
День отдаёт столько сценариев, сколько в нём пунктов задания, — каждый в 1–3
колонки, чтобы всё влезало в кадр без горизонтального скролла.

Провайдер — [OpenRouter](https://openrouter.ai) (OpenAI-совместимый API,
одна модель на колонку, `usage.cost` в каждом ответе).

## Запуск

```bash
cp .env.example .env          # впишите OPENROUTER_API_KEY
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Откройте http://127.0.0.1:8000 — слева список сценариев по дням.

`.env` в `.gitignore`. Репозиторий публичный: ключ, попавший в коммит, отозвать уже
нельзя. Никогда не коммитьте через `git add -A`.

Дропдаун моделей работает и без ключа: каталог `/api/v1/models` авторизации не требует.

## Структура

```
app/                 стенд, общий для всех дней — заморожен
  main.py            FastAPI: сценарии, прогон, ручной чат, SSE-потоки
  registry.py        автоподхват day-*/scenario.py, группировка по дням
  schema.py          Scenario / Session — контракт
  llm.py             стриминг OpenRouter и сбор метрик
  catalog.py         /api/v1/models с кэшем и фильтрами
  config.py          поиск ключа
  static/            index.html, app.js, style.css
docs/CONTRACT.md     как написать сценарий дня
day-NN/              один день: scenario.py (список сценариев) + README.md
```

## Что показывает стенд

Колонка устроена как чат: сверху лента сообщений, под ней метрики, внизу поле
ввода. Промпт из `Session.messages` виден **до** нажатия «Старт»: `system` идёт
приглушённым блоком и сворачивается по клику, `user` — заметным пузырём. Ответ
модели стримится под ними как `assistant`. У колонки с `depends_on` до старта
подсвечен литерал `{{depends_on}}`, а на старте стенд перерисовывает ленту
итоговым промптом — уже с подстановкой.

Раскладка на всю высоту экрана: страница не скроллится ни по одной оси,
скроллится только лента внутри колонки. Колонки делят ширину поровну, на узком
экране встают друг под друга. `description` и `watch_for` сценария спрятаны за
кнопкой «О сценарии» и свёрнуты по умолчанию.

В поле под лентой можно **писать модели руками** — до прогона и после. В модель
уходит вся накопленная лента колонки, поэтому диалог продолжается; параметры
стенд берёт из `Session`, модель — из селектора в шапке. Enter отправляет,
Shift+Enter переносит строку. Без ключа поле недоступно и говорит, чего не хватает.

Когда все колонки отработали, под ними появляется блок **«Вердикт»**. Отдельная
модель-судья отвечает на вопросы задания дня: сравнивает ответы колонок
и формулирует вывод. Её ответ стримится в кадр так же, как ответы колонок.
Судья зовётся один раз за прогон и только у сценариев, где заданы
`judge_questions`, а стоимость этого вызова идёт в сводке отдельной строкой.
Подробности — в [docs/CONTRACT.md](docs/CONTRACT.md).

На каждую колонку, в реальном времени: TTFT, скорость в ток/с, счётчик
сгенерированных токенов, прошедшее время, `prompt`/`completion`/`total` токены,
reasoning-токены, стоимость в долларах, `finish_reason`, модель и фактический
провайдер, заполнение контекста в процентах. По прогону: суммарная стоимость,
суммарные токены, wall-clock, стоимость судьи, а когда колонок больше одной —
ещё самая быстрая и самая дешёвая из них.

## Добавить день

Создайте `day-NN/scenario.py` по [docs/CONTRACT.md](docs/CONTRACT.md): объявите
`SCENARIOS` — список сценариев дня, `id` каждого начинается с имени папки
(`day-02-format`) и уникален глобально. Реестр подхватит их при следующем запросе
списка — трогать `app/` не нужно. День, нарушивший контракт, попадёт в ошибки под
списком сценариев и не сломает остальные дни.
